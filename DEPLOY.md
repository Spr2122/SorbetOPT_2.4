# Выкладка на VPS

Схема простая: сайт собирается **на вашем компьютере**, готовые файлы загружаются на сервер по SSH
в новую папку `releases/ДАТА-ВРЕМЯ`, после чего ссылка `current` атомарно переключается на неё.
На сервере нужен только Caddy — Node.js, базы данных и фоновые сервисы не нужны.

```
/var/www/sorbentopt/
├── current -> releases/20261201-103015     ← отсюда Caddy отдаёт сайт
└── releases/
    ├── 20261201-103015/   (текущая)
    ├── 20261124-091200/   (предыдущая — для отката)
    └── …                  (приложение хранит последние 5)
```

Откат на предыдущую версию — кнопка в приложении («Публикация → Откатить»), занимает секунду.

## Первоначальная настройка сервера (один раз)

1. Зайдите на сервер по SSH и выполните `deploy/setup-vps.sh` от root — он создаёт пользователя `deploy`
   и каталоги.
2. В приложении откройте **Настройки → Сервер**, заполните адрес сервера, пользователя `deploy`
   и нажмите **«Создать SSH-ключ»**. Скопируйте показанный публичный ключ в
   `/home/deploy/.ssh/authorized_keys` на сервере.
3. Установите [Caddy](https://caddyserver.com/docs/install), поместите `Caddyfile` из репозитория
   в `/etc/caddy/Caddyfile`, выполните `systemctl reload caddy`.
4. Направьте A-запись домена на IP сервера. Сертификат HTTPS Caddy получит сам.
5. В приложении нажмите **«Проверить подключение»** и подтвердите отпечаток сервера (один раз).

## Обычная работа

1. Меняете товары / контент в приложении.
2. **Публикация → «Проверить»** — приложение найдёт ошибки и покажет список изменений с прошлой выкладки.
3. **«Собрать»**, затем при желании **«Предпросмотр»** (откроется локальная копия).
4. **«Выложить на сайт»**. После загрузки приложение проверит, что сайт открывается.

## Безопасность

* Для выкладки используется отдельный пользователь `deploy` без пароля и без прав администратора.
* Приложение запоминает отпечаток сервера и откажется подключаться, если он изменится.
* Пароли и пассфразы хранятся в защищённом хранилище ОС (если оно доступно), либо не сохраняются.
